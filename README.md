# 帧工坊 · 原片人物与场景替换

本地网页工具，用原视频作为动作、镜头、节奏与原声依据，整理人物和场景替换材料、验收 Wan3 原始回片，再按原切点拼接并接入音频。人工和 Codex 使用同一个网页，工具可独立运行。

## 在 Codex 中一句话开始

在本机 Codex 打开这个仓库的根目录。仓库中的 [AGENTS.md](AGENTS.md) 会引导 Codex 阅读首次使用说明和[制作手册](docs/帧工坊新会话制作手册.md)。

首次使用只需发送：

```text
启动帧工坊。
```

工作台启动后，附上原视频、角色或场景参考素材（附件或本机路径），再发送：

```text
按制作手册，用我提供的素材制作视频。
```

Codex 会先核对素材、替换要求、输出规格与费用，再按本批明确授权提交。已有且内容一致的授权继续有效。

## 首次使用（macOS）

当前双击启动器面向 macOS；尚未提供 Windows 原生启动器。其他系统请先让 Codex 核对运行条件。公开仓库只有源码、测试与通用文档，没有原作者的素材、项目数据或 API Key；首次启动进入空工作台，使用自己的文件新建项目。

以下命令均在仓库根目录执行；该目录应直接包含 `backend/`、`frontend/` 和 `启动帧工坊.command`。通过 Git 获取源码时：

```sh
git clone https://github.com/xiaohu65/frame-studio.git
cd frame-studio
```

### 1. 准备运行环境

| 依赖 | 用途 |
| --- | --- |
| Python 3.12 或更新版本 | 本地服务；使用独立虚拟环境 |
| Node.js 22.13+ 的 LTS 版本及 npm | 首次安装前端依赖与构建页面 |
| ffmpeg、ffprobe | 读取、检查与封装视频；均须能从启动终端找到 |

创建项目独立环境并安装 Python 依赖（以下使用 `python3.12`；若本机 `python3` 已是 3.12 或更新版本，也可使用该命令）：

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

通用人物与场景替换流程不依赖 Blender。历史人偶工具需要的 Blender、姿态模型和可选音频分离环境，按对应功能另外准备。依赖原作者私人素材的旧 `backend/seed.py` 入口已停用，新项目通过网页创建。

### 2. 启动并打开工作台

双击 `启动帧工坊.command`，或在终端执行：

```sh
./启动帧工坊.command
```

启动器按以下顺序选择 Python：显式设置的 `FRAME_STUDIO_PYTHON`、仓库 `.venv/bin/python`、已激活环境的 `VIRTUAL_ENV/bin/python`、PATH 中的 `python3`。显式配置无效时会报错，不会悄悄换用其他环境。使用仓库外的环境时，可指定其 Python 路径：

```sh
FRAME_STUDIO_PYTHON="/path/to/env/bin/python" ./启动帧工坊.command
```

启动器检查依赖，不自动安装或修改 Python 环境。首次缺少前端依赖和构建时，会执行 `npm ci` 并构建页面；需要联网下载 npm 依赖。成功后保留终端窗口，在已有浏览器会话的地址栏输入 `http://127.0.0.1:8765/`。服务只监听本机，启动器不会另开浏览器。

### 3. 配置并开始使用

在工作台新建项目，导入自己的原视频和参考素材。需要 Wan3 API 时，在网页的「API 设置」中填写自己的 Key、业务空间和地域；不要把 Key 发到对话或提交到仓库。没有 Key 时可使用当前可用的本地材料整理与素材包流程。

首次启动与页面检查不上传素材、不调用付费生成。生成前核对实际上传清单、规格、预计费用和预留上限，再确认对应批次的上传与费用授权。浏览器验证只检查桌面端，并复用同一个现有会话。

### 4. 停止与下次启动

先保存网页草稿、等待活动任务结束，再回到原终端窗口按 Control-C。下次直接双击或运行同一启动脚本；依赖与有效构建会复用。更新、版本诊断和任务异常处理见下节。

## 启动、更新与故障诊断

双击启动脚本后**保留终端运行窗口**，不要用 `nohup` 当作本机常驻服务方案。启动器不会打开浏览器；在已有浏览器会话的地址栏输入 `http://127.0.0.1:8765/`。重复启动会识别并复用此项目的现有服务，不重启、不恢复覆盖任务，也不停止占用端口的其他程序。

脚本按自身位置定位完整项目，按上文顺序选择 Python，并检查 Python 版本、Pillow、NumPy、ffmpeg 和 ffprobe。可用 `FRAME_STUDIO_PYTHON` 指向已准备好的环境；不会自动重装 Python 依赖。旧人偶流程需要的 Blender、姿态模型等仍按各自功能检查。

前端源码、依赖锁定文件或构建文件变化后，下次**没有运行服务且没有待核查任务**时才重新构建；有可信且完整的当前构建就直接复用。需要构建时才检查 Node.js/npm；只有依赖缺失、安装校验失败或锁定版本不同才执行 `npm ci`。构建先在临时目录完成，失败时保留旧构建并停止启动，避免悄悄显示旧页面。第一次使用新启动器时，旧 `dist` 因没有版本记录会重建一次。

在项目目录执行以下只读检查（也可给双击脚本传同样参数）：

```sh
./启动帧工坊.command --status
./启动帧工坊.command --json
```

诊断显示本机入口、项目目录、页面源码/构建指纹及日志目录；新启动器还记录进程启动时的后端版本和页面版本。旧方式启动的服务没有运行版本记录，诊断会明确显示「无法确认」，不会把磁盘上的新代码误报成已生效。`--status` / `--json` 不构建、不启动、不恢复任务、不写项目或诊断文件。JSON 可供主会话或以后页面诊断集成使用，当前没有新增后端路由。

现有 Vite 开发入口如使用 8766，可执行 `./启动帧工坊.command --status --port 8766` 单独检查；该页面直接来自源码，API 代理到 8765，与后端静态入口使用的 `dist` 不同。诊断无法判断浏览器当前标签页的缓存版本，网页内版本展示与浏览器验证由主会话另行集成。

更新时先在网页保存草稿，确认没有待保存内容、活动任务或待核查生成批次；再到**原运行窗口**按 Control-C 停止，然后重新双击启动。新启动器收到停止请求时若发现活动或待核查任务会继续保留服务。不要强制退出窗口，不要删除任务记录来绕过检查。服务已离线却遗留活动、提交状态不明、下载失败或不可读取的任务记录时，启动器会停在核查提示，不主动执行后端恢复、云端查询/下载或重复生成；将任务记录和已有结果交回制作会话安排人工恢复。直接执行 `python -m backend.server` 会绕过这些启动检查，现有该入口的恢复顺序未在本次修改。

失败可按提示处理：

| 现象 | 下一步 |
| --- | --- |
| 浏览器连接失败、诊断显示没有服务 | 双击启动脚本，保留终端窗口，查看窗口中最先出现的错误；确认使用诊断给出的地址和端口。 |
| 端口被其他服务占用或归属无法确认 | 查看原运行窗口和端口归属；启动器不会自动杀进程、换公网监听或另起浏览器。若确需不同本机端口，可显式传 `--port 端口号`，不要为活动项目重复启动第二份服务。 |
| 前端构建较旧，或后端运行版本与源码不同 | 先保存草稿、等待任务结束，再按上述步骤手动更新；已运行服务不会被启动器自动重建或重启。 |
| 入口返回 403「仅允许本机访问」 | 在已有浏览器的地址栏手动输入本机入口，避免从外站链接直接跳入；若仍失败，保留地址、时间和错误截图交回排查。不要关闭 Host / Origin / Fetch-Site 保护。 |
| 页面构建失败、服务退出 | 打开启动窗口给出的本次日志。缺依赖等构建前失败会直接显示在窗口；旧方式启动的进程没有新日志，查看其原运行窗口。 |

新日志默认在 `~/Library/Logs/FrameStudio/项目目录指纹/`，包含构建输出和本次服务输出；启动窗口显示具体路径。运行记录只用于诊断，不用于自动停止或接管进程。`FRAME_STUDIO_RUNTIME` 可改诊断目录，`FRAME_STUDIO_DATA` 可选数据根；不要在同一端口混用不同数据根。启动器不会读取 Key/私有配置来诊断。若系统缺少 `lsof` 或无法读取进程归属，按「无法确认」处理，不猜测并接管。

从仓库网页、外站链接或自动化入口跳入本机页面后若出现 403，请在同一浏览器会话的地址栏直接输入本机入口；首次启动检查已验证这种进入方式。保留现有 Host / Origin / Fetch-Site 保护，不以关闭访问保护解决入口问题。

## 播放对象与提交文件

点击分段或时间轴默认播放该段的实际参考文件，显示原片区间、文件名和读取时长。「原片全片（不提交）」单独查看完整素材，不会改变提交文件。尚未准备分段时只能预览原片选区，页面明确标注，并在选区末尾暂停。对照模式在同一区间同步播放、定位、暂停和重播；文件时长超过一帧容差时提示重新检查。生成前预检另外核验实际文件，禁止用全片预览冒充分段输入。

网页地址记录当前项目、步骤、片段和查看方式；刷新后可恢复。检查页按问题类型分组并提供处理入口，全部阻断项仍保留。

## 整部剧与角色连续性

在「剧集与角色库」创建一部剧，为每集关联独立项目；也可一次创建1–100集空白工作区。空白工作区不表示视频已导入或人物已识别。

为原剧角色建立固定角色ID，记录别名和辨认依据；从已经导入的目标角色图片发布冻结版本。每一集的原片人物单独绑定该角色及明确版本，并确认身份。全剧角色ID属于本地记录，不是Wan的原片人物硬控制参数。

发布v2不会静默覆盖已经绑定v1的集数。页面可筛选待绑定、待确认、待复核和有新版素材的集数；升级版本后必须重新检查相关素材与审核。服装和年龄变化需在角色描述与定位观察中明确，工具不会自动把长相相似者判为同一角色。

固定素材与映射可以减少输入错配；模型输出仍须逐镜核对，尤其多人打斗、遮挡与换装。100集管理测试只验证工作区、编号和版本约束，不等于100集实际视频已自动准确换角。

## 白模是否必要

默认直接编辑原片，不需要先制作白模。已有清楚的真人动作，尤其要求保留武打、触球、甩镜和接触时点时，优先保留原片参考及保护范围。白模适合另行设计新动作、新机位或没有合格运动参考时的预演；错误的白模会把动作与身体错误带到后续结果，不能代替准确人物绑定或遮罩。

## 使用流程

1. **原片与分段**：从电脑选择原片或填绝对路径导入本机。每段不超过15秒，参考沿用原尺寸、原分数帧率与实际帧序。
2. **人物对应**：为原片人物建立固定编号、辨认依据，选择换头、整个人物外观或保持原样，绑定目标角色图。换镜头继续用同一编号，在交叉、遮挡和出入画处补充定位观察。定位框仅用于身份核对。
3. **场景与范围**：保留原场景，或指定新场景图和外观范围。原片轮廓和前景保护记录用于核对目标、遮挡及生成要求。
4. **生成视频**：核对原片参考、实际图片、逐镜提示词、输出规格与费用。按本批授权提交 Wan3，或在无 Key 时导出素材包。输入变更会使旧准备和审核失效。
5. **验收与导出**：直接检查 Wan3 原始回片的规格与时间轴，并对照原片逐段验收。通过后按原切点拼接并接入一次连续原声。首轮结果未通过时记录问题并停止交付。

## 人工与 Codex 共用网页

控件具备明确名称、标签与状态；人物、片段和素材有固定编号。定位、描轮廓同时支持画面操作与数字输入。未保存编辑在当前浏览器会话中保留；保存核对项目版本，旧页面不能静默覆盖新修改。

验收绑定原片、材料、片段范围和原始回片的实际文件。输入变化后旧输出保留为历史，旧合成或适配记录不能充当原始回片验收。规格检查与人工效果验收分别完成。

浏览器自动化复用同一个已有会话，串行测试，不另起浏览器或无头实例。

## 云端范围及当前封锁

仅适配阿里 Wan 视频系列。当前适配器为 `wan3.0-video` 和 `wan3.0-video-prime`；后续版本核对官方能力、费用和参数后适配，不自动切换模型。

云端操作需要按当前批次核对材料、设置、报价并明确确认；修改预算不能代替授权。`system.cloud_upload_enabled=false` 等旧全局状态字段与 `generation` 的逐批授权不是同一层含义，不能据此宣称当前批次已授权或生成通路完全不可用。以该批次准备和确认状态为准；启动诊断不解锁、不确认、不提交，也不自动查询或下载任务。密钥不进入提示词、素材包或页面返回。

Wan3 当前输出固定30fps。严格模式下源片非30fps会在云端兼容性预检中阻断。直拼要求各段原始回片与原片时间轴和尺寸一致，且视频编码配置彼此兼容。发现规格冲突时停止导出。

本地编号不是 Wan 的原片人物硬绑定字段，多张图也不保证十人打斗自动对应。工具用明确映射、逐处观察、遮罩和审核减少错配，无法确认时保留待修复状态，不宣称任意视频全自动1:1换角。

## 输出与验收

- 原片分段参考、人物定位核对图、逐段图片引用清单、完整提示词和ZIP素材包。
- 原片参考经过编码，帧序与时间轴单独检查，不宣称参考图像像素无损。
- 最终 MP4 直接复制已验收的原始视频流，回读验证视频包、解码帧和相对时间戳。仅接入一次连续原声，保留原音画起点。
- 旧合成、适配和成片文件保留为历史记录。当前生产导出只使用已验收的原始回片。
- 人工轮廓只在同编号、同点序与同顶点数之间插值；出画、遮挡断点与切镜处须补相邻帧关键帧，不跨未知区间推测。
